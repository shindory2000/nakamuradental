# LINE 経過観察（中村歯科医院）

会計待ちに LINE を友だち追加 → 1週間後に経過をうかがう → 必要なら受診の希望日 → 全員に同じ文面で Google 口コミ（任意）。

| ファイル | 役割 |
|---|---|
| `index.html` | LINE の中で開く画面（LIFF）。当日の登録と、1週間後の希望日。`?demo=1` で送信なしの確認用 |
| `demo.html` | 院長・本人向けの確認用（当日の画面・トーク・希望日の3つを並べて触れる） |
| `card.html` | 受付の QR（A4 に2枚）。LIFF ID を入れると QR が出る |
| `../apps-script/Followup.gs` | 本体（Apps Script）。`Code.gs` と同じプロジェクトに入れる。文面は `FU_MSG` にまとめてある |

## 3人の点検で決めたこと（2026/11/9）

UI・UX、医院の現場、MEO・規約の3つの立場で点検し、元の案から次の点を変えた。

1. **［はい］で Google の口コミ画面を自動で開くのをやめた**
   - Google の規約は、店内にいる人に投稿を求めたり、圧をかけたりすることを禁じている。
   - 患者さんにも「同意しただけなのに口コミに飛ばされた」と受け取られやすい。
   - そこで［受け取る］は経過のご連絡への同意だけにした。登録後の画面に「口コミを書く（任意）」のボタンを別に置く。［受け取らない］の人にも同じボタンを出す。
2. **口コミの案内は、3つの答えすべてに同じ文面で出す**
   - 「問題ない」の人だけに出すと、Google が禁じる「良い口コミだけを選んで頼む」に当たる。
   - 出すタイミングは答えごとに違う。
     - 問題ない：すぐ
     - もう一度診てほしい：希望日を送った後
     - 少し気になる：医院が対応して「対応済み」にした翌朝。症状への対応を先にするため。
3. **希望日は LINE の日付選択を3回させず、1画面にした**
   - 日付は休診日を除いた一覧から選ぶ。時間帯は「午前／15〜17時／17〜19時／いつでも」で、土曜は17時まで。
   - 送ると、希望がトークに患者さんの発言として残る。スタッフのアプリに通知が届き、そのままチャットで返信できる。
   - 毎回「まだ予約は確定していません」と出す。
4. **フリガナを1回だけ入れてもらう**
   - LINE の名前だけでは、カルテの誰か分からないため。
   - 「受診された方の」と書き、家族の LINE で受け取る場合にも対応する。
5. **症状の相談には必ず注意書きを付ける**
   - 返信は診療時間内であること。
   - 腫れ・出血・発熱のときはお電話、時間外は #7119。
   - 時間外にトークが来たら、6時間に1回だけ自動で返す。
6. **個人情報の扱い**
   - 症状は要配慮個人情報なので、同意のチェック欄と「取り扱いについて」を付けた。
   - メールの通知には症状を書かない。
   - トークで「停止」と送れば止まる。
7. **1週間後の連絡は、診療日の10時に送る**
   - 日曜・祝日・臨時休診に当たる場合は、次の診療日に送る。
8. **当日のお礼は「笑顔を守ります」をやめ、「お大事になさってください」にした**
   - 医院が出す文面は広告に当たるため、効果や結果を約束する言い方を避けた。

## やってはいけないこと（受付・スタッフ向け）

- 患者さんのスマホを操作する、画面をのぞく、院の端末で投稿させる。
- 口コミのお礼に割引や粗品を付ける。星5を頼む。書く内容を例示する。担当者の名前を書くよう頼む。
- 口コミの件数をスタッフのノルマにする。
- 口コミを医院のホームページ・LINE・ポスターに転載する（医療広告ガイドラインの体験談に当たる）。
- LINE の症状相談に、院長以外が医療的な判断で答える。返信は「ご来院かお電話を」を基本にする。

## 院長に確認すること

1. 案内する患者さん
   - 現場担当の推奨：その日に処置があり、次の予約が無いか2週間以上先の人。抜歯・根の治療・被せ物や入れ歯を入れた後など。
   - 検診だけの人、1週間以内に次の予約がある人は外す。
2. 症状に返信する人（院長だけか）と、不在のときの代わり。LINE を確認する時間（始業・昼・終業の1日3回が目安）。
3. 文面（`Followup.gs` の `FU_MSG` と `index.html`）。
4. 保存先：記録のスプレッドシートを医院名義の Google アカウントに置くこと。見る人。保存期間は「対応後1年で削除」。
5. LINE の費用
   - 無料プランは月200通まで。1人あたり2通（当日のお礼・1週間後）で、月100人まで。
   - 超える場合はライトプラン（月5,000円）。または `FU_THANKS_PUSH=false` で1人1通（月200人まで）。
6. プライバシーポリシーに LINE での経過連絡を追記してよいか。

## 立ち上げの手順

**医院か本人がやること**
- LINE 公式アカウントの作成（医院名義）
- LINE Developers のログイン
- Apps Script の公開と定期実行の許可

**私ができること**
- 公開後の値の入れ込み
- 試験
- 画面の公開

1. **LINE 公式アカウント**（医院名義）を作る。
   - 設定 → Messaging API を有効にする。
   - 応答設定は「チャット：オン」「Webhook：オン」「応答メッセージ：オフ」「あいさつメッセージ：オフ」にする。あいさつは `Followup.gs` が返す。
2. **LINE Developers**
   - 同じプロバイダーに「LINE ログイン」チャネルを作る。
   - その中に LIFF を追加する。
     - サイズ：Full
     - エンドポイント：`https://nakamuradental.jp/line/`
     - スコープ：openid・profile・chat_message.write
     - 友だち追加オプション：On（Aggressive）
   - LINE ログインチャネルの「リンクされたボット」に、1の公式アカウントを指定する。
3. **Apps Script**（台帳シート「中村歯科 発信の確認台帳」のスクリプト）
   - `Followup.gs` を追加し、`Code.gs` を差し替える。
   - スクリプト プロパティを入れる。
     - `LINE_TOKEN`（Messaging API の長期トークン）
     - `LIFF_CHANNEL_ID`
     - `LIFF_ID`
     - `FU_TEST_USER_IDS`
     - `CLINIC_EMAILS`（任意）
   - `setup()` → `setupFollowup()` の順に実行する。
   - ウェブアプリとして公開し、Webhook URL に `…/exec?k=<WEBHOOK_KEY>` を登録する。
4. **画面の公開**
   - `index.html` の `LIFF_ID`・`GAS_URL` を埋める。
   - `line/index.html` にコピーし、`robots.txt` に `Disallow: /line/` を足して push する。
5. **試験**
   - 試験する人の LINE ユーザー ID を `FU_TEST_USER_IDS` に入れる。
   - `FU_DAYS` を一時的に 0 にし、`sendFollowups` を手で実行して、3つの分岐を通す。
6. **院長の OK が出たら**
   - `FU_LIVE=true` にする。
   - `card.html` に LIFF ID を入れて印刷し、受付に置く。
